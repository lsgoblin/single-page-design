# Single Page Design

从 `ppt-simplify` 剥离的独立技能，聚焦单页 PPT-layout 与用户图片的样式改造。通过本机浏览器展厅预览资源，在对话中完成需求表达与修改，查看更新后的结果，再确认导出。

本文记录已确认的产品定位、目录分工与工作流程。当前已对齐模板/样张资源组织；完整 PPT 生成工作流和可用展厅仍需后续实施。

## 已确认的使用流程

**本机启动 → 加载技能包 → 浏览样式 → 选择样式 → 在对话中提出内容与修改要求 → 浏览器更新预览 → 确认导出。**

| 环节 | 用户与技能的行为 |
|---|---|
| 本机启动 | 在用户电脑上启动展厅服务，通过本机浏览器访问。 |
| 加载技能包 | 从当前 `single-page-design` 包内加载资源索引、样式说明、预览图与单页 layout；整个包可独立迁移。 |
| 浏览样式 | 展厅仅设置“单页 PPT-layout”和“图片改造”两类内容，支持查看完整效果与说明。 |
| 选择样式 | 用户选择单页 layout，或选择针对输入图片的改造与排版样式；选择作为后续对话与生成流程的输入。 |
| 在对话中提出内容与修改要求 | 用户在对话中提供文案、图片、用途与调整要求，由技能执行相应流程。 |
| 浏览器更新预览 | 展示生成或修改后的最新作品；用户继续在对话中提出要求，再查看更新结果，直至满意。 |
| 确认导出 | 用户确认结果后，完成对应内容的检查与导出。 |

浏览器承担资源浏览、样式选择和结果预览；内容修改由对话驱动。浏览器内文本编辑、拖拽排版等编辑器功能不属于当前已确认范围。

## 目录分工

`templates/` 保存两种模式下可复用、可选择、可应用的模板资源；`references/` 保存与模板对应的样板样张。二者用相同模板 ID 建立对应关系。

```text
single-page-design/
├── templates/
│   ├── page_layouts/<id>/       单页结构规格、SVG 和应用所需素材
│   ├── image_styles/<id>/       图片改造模板与应用规则
│   └── color_palettes/<id>/     两种模式共用的配色定义
├── references/
│   ├── page_layouts/<id>/       对应单页样张与样张说明
│   ├── image_styles/<id>/       对应图片改造样张与样张说明
│   └── color_palettes/          对应配色色块样张与整体预览
├── workflows/                  两种模式的执行说明
├── scripts/                    工具与运行代码
└── provenance.json             来源与提取记录
```

模板发现分别使用 `templates/page_layouts/page_layouts_index.json` 与 `templates/image_styles/image_styles_index.json`，索引指向模板及其对应样张。样张供浏览和比较，不替代用户输入，也不作为生成步骤的执行依据。模板中的 `images/`、`icons/` 则保留实际应用所需的素材。

详见 [模板资源说明](templates/README.md) 与 [样板样张说明](references/README.md)。当前发现入口使用新结构，已按用户确认的清单清理旧路径副本。

## 两类内容

### 1. 单页 PPT-layout

资源是适用于一页 PPT 的 layout，包括完整页面预览、版式说明、可替换区域及必要素材。交付是一页可编辑 PPT 与预览图。

**生成流程完全按照 `ppt-simplify` 中对应的流程执行。** 单页是交付范围，不构成压缩、替换或跳过原流程的理由；不得另设“选择模板 → 替换文字 → 直接导出”的简化生成流程。

以原普通生成流程为例，其顺序为：

1. 处理用户的内容与初始材料，按原条件补充事实研究。
2. 初始化项目并导入材料。
3. 准备模板候选。
4. 执行策划阶段：第一阶段确认沟通目标与模板选择；按确认结果安装模板；第二阶段确认完整方案与制作安排。
5. 按需准备图片资源。
6. 执行页面制作、实时预览与质量检查。
7. 按原要求后处理并导出。

上述条目用于说明原流程，不替代原流程的详细规定。路由、角色、确认节点、素材准备、质量门和导出要求，均以 `ppt-simplify` 的对应流程为依据；普通生成遵循其 `workflows/generate-pptx.md`。不得因为只有一页、已在展厅选择 layout，或已有预览图，就自动进入 Quick 或跳过确认。展厅选择作为候选输入，仍须衔接原流程中的模板确认与安装。

独立包后续需要携带所需流程及其依赖，不能在运行时依赖原仓库；具体提取与对齐属于后续实施工作。

### 2. 图片改造

**以用户输入的图片为起点，将其改造为不同样式的图片排版作品。** 样式既可以改变图片的视觉表现，也可以改变图片与文字、纸张、抽象面板等元素的组合排版。

例如：

- 将输入照片重构为撕纸拼贴、水彩、剪纸等视觉形式。
- 保留原片，配合从原片提炼的抽象面板组成排版作品。
- 将输入图片组织成杂志、海报等不同版式。

海报、杂志排版等属于图片改造内部的样式，不另设第三类内容。独立的“仅输入主题、从零生成海报”不在本次确认范围内。

展厅为每种样式展示效果参考；适合对照的样式展示原图与改造结果，帮助用户理解视觉变化。实际制作时以用户当前输入的图片为内容来源，不把展示样例中的主体或文案固定到新作品中。

技能根据输入图片、所选样式、用途和修改要求组织提示词，调用可用图像能力完成改造与排版，再更新浏览器预览。主体、身份、空间关系、原片是否允许重绘，以及文字与构图的变化范围，按当前用户要求确定。用户只要提示词时，直接在聊天框输出，不保存为提示词 `.md` 文件。

## 共用配色库

已将用户参考色卡整理为 56 组五色配色（P01–P56，280 个色位），可与任意单页版式或图片改造模板组合。入口为 `templates/color_palettes/color_palettes_index.json`，定义、样张及来源记录随包保存，不依赖 `drafts/`。查看 [整体色卡预览](references/color_palettes/overview.svg) 或 [配色使用说明](workflows/color-palette.md)。原图标注和采样值均保留，P44 第 3 色的标注错误已注明。

配色属于现有两种模式共用的资源；独立展厅的配色选择界面尚未开发。
