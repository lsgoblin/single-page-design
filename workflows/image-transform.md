# 图片改造模式

以用户输入的图片为内容来源，将其改造为所选视觉风格。海报、杂志、原片与抽象面板等都是本模式内部的样式形式。需要一图一句直接排版，或要点名色卡 / 字体时，进入 [图片排版模式](image-layout.md)；两者都以用户图片为内容来源，图片排版不读取 `image_styles` 模板。

## 选择与应用

1. 从 `templates/image_styles/image_styles_index.json` 查看已注册的 16 个风格。按用户当前参考图和描述选择；只读取选中模板的 `template.json` 和对应样张。模板里的 `source_prompt` 是原始风格定义，`prompt_assembly` 说明如何把它换成当前任务。
2. 查看用户输入图片，结合用途、比例、文案与修改要求，明确主体、身份、空间关系、允许重绘范围和文字策略。缺少用户图片时先取得图片，不能以样张代替输入。
3. 根据用户参考图和描述确定构图、材质、主体保留和误差限制；有已注册且选中的模板时结合其规则，组织当前任务提示词。只要提示词时直接在聊天框输出，不创建提示词 `.md`，不自动生图。
4. 用户要成图时，通过宿主可用图像能力传入实际参考图/编辑目标进行处理；不要只传文字而假装用了原图。没有可用图像工具时说明完成范围，不把提示词说成成图。
5. 查看生成结果，核对主体、关键物件、空间关系、材质、文字与比例，修正实质偏差；在浏览器更新预览，继续接收对话修改，用户确认后导出。

严格保留原片的任务应保持原照片区域不重绘，生成的抽象/插画面板单独制作后组合。撕纸拼贴等允许重绘的任务则按用户要求保留辨识特征和主要关系，不把统一“不重绘”规则套到所有模板。

## 样张的用途

`references/image_styles/<id>/` 保存与模板同 ID 的样张、`sample.json` 和来源记录（平台、作者、原帖、发布日期）。样张只说明视觉语言：其中的人物、地点、文字、配色与版式不绑定未来任务，也不宣称每项都做过同一原图的真实改造验证。

实际任务的输出属于任务工作目录，不写回模板或样张库。只有用户要求入库时才新增模板、样张并更新索引。


## 可选配色

需要从色卡库选色时，读取 [共用配色说明](color-palette.md)，从 `templates/color_palettes/color_palettes_index.json` 选择配色。保留配色编号与实际色值，按当前模式应用；用户既有品牌色、原片保留要求及原确认流程优先。
