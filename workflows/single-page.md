# 单页 PPT-layout 模式

用户在本机展厅浏览样张，选择模板，在对话中提出内容与修改要求。展厅选择是后续原流程的候选输入，不替代其确认节点。

## 资源入口

读取 `templates/page_layouts/page_layouts_index.json`，再读取选中条目的 `template` 与 `reference`。模板定义在 `templates/page_layouts/<id>/`，样张在 `references/page_layouts/<id>/`，二者以相同 ID 对应。

当前有图文渐隐信息页、大字与前景穿插封面、双纸层斜向开窗三个模板。样张仅说明效果；实际文案、图片与应用方式由用户需求和原流程决定。

## 生成流程

完整继承 `ppt-simplify` 中对应的生成流程，包括路由、角色、材料处理、项目初始化、候选准备、策划阶段两次确认、模板安装、素材准备、页面制作与实时预览、质量检查、后处理和导出。普通生成不能因只有一页或已有模板而进入 Quick。

当前包尚未完整迁入原 `workflows/generate-pptx.md` 及其依赖。该迁移完成前，不将现有底层 `single_page.py init/export` 或展厅原型当作完整生成流程，也不宣称已完成流程对齐。正式生成所需的缺口应明确报告，不能用“替换文字后直接导出”补位。

迁移后的运行入口应在本包内，不能依赖原仓库的绝对路径。本轮目录整理不进行该流程迁移，也不新增流程捷径。

## 结果预览

修改在对话中提出，由技能执行后更新浏览器中的当前作品预览。导出前遵循原质量要求；SVG 源画面预览与 PowerPoint 实际渲染须明确区分。浏览器文本编辑和拖拽排版不属于当前确认的展厅范围。


## 可选配色

需要从色卡库选色时，读取 [共用配色说明](color-palette.md)，从 `templates/color_palettes/color_palettes_index.json` 选择配色。保留配色编号与实际色值，按当前模式应用；用户既有品牌色、原片保留要求及原确认流程优先。
